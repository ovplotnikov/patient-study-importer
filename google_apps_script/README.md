# Приёмник счётчиков в Google Drive

Настольная программа отправляет только сводные счётчики. Веб-приложение Apps Script проверяет сообщение и обновляет отдельную приватную таблицу Google. Программа не получает ссылку на таблицу, токен Google или доступ к чтению. Подключение этого варианта требует настройки и проверки владельцем.

## Настройка владельцем

1. Создайте новый самостоятельный проект на [script.google.com](https://script.google.com/). Вставьте `Code.gs` в файл скрипта. В настройках проекта включите отображение манифеста `appsscript.json` и вставьте его содержимое. В списке сервисов должен появиться **Google Sheets API v4**. [Расширенные сервисы Apps Script](https://developers.google.com/apps-script/guides/services/advanced).
2. В редакторе выберите `initializeSpreadsheet` и выполните один раз под своим аккаунтом. Скрипт создаст отдельную таблицу «Исследования пациентов — диагностика» с вкладкой «Приём» и сохранит её ID в **Свойствах скрипта → SPREADSHEET_ID**. Разрешение `drive.file` даёт доступ только к файлам, созданным или явно открытым через приложение. [Области доступа Sheets](https://developers.google.com/workspace/sheets/api/scopes).
3. Откройте таблицу на Диске и убедитесь, что общий доступ ограничен.
4. В **Развернуть → Новое развертывание → Веб-приложение** выберите выполнение от имени владельца и доступ «Все», включая посетителей без входа в Google. Скопируйте в настройки клиента базовый URL, который заканчивается на `/exec`. [Веб-приложения Apps Script](https://developers.google.com/apps-script/guides/web).

## Переход действующего приёмника на вторую версию

Программы 2.4.0–2.5.2 продолжают отправлять сообщения схемы 1, новые версии — схемы 2. Новый `Code.gs` принимает обе. Порядок для владельца:

1. Откройте существующий проект Apps Script и сохраните копию прежнего `Code.gs` (на случай отката).
2. Замените содержимое `Code.gs` новым из репозитория. `appsscript.json` не менялся.
3. В редакторе выберите `initializeSpreadsheet` и выполните один раз. Скрипт использует сохранённую таблицу, добавит вкладку «Приём» и не тронет прежнюю вкладку «Счётчики»: её суммы остаются как были.
4. **Развернуть → Управление развертываниями → (действующее развертывание) → Изменить → Версия: новая версия → Развернуть.** Адрес `/exec` должен остаться прежним: он зашит в установленные программы. Новое развертывание с новым адресом создавать не нужно.
5. Проверьте приём на вымышленных данных (ниже). В таблице должна появиться вкладка текущей недели, например `2026-W47`, и строка в «Приём».
6. Список версий больше вести не нужно: приёмник принимает любую версию вида `x.y.z`.

## Проверка развёртывания

Сначала используйте отдельный тестовый проект и таблицу. Оба запроса должны вернуть `{"ok":true}`. GET проверяет доступность и не читает таблицу. POST отправляет вымышленную сводку: на вкладке недели появятся две строки по 1, на вкладке «Приём» — `accepted schema_2`. Запрос с лишним полем должен вернуть `{"ok":false}` и добавить в «Приём» строку `refused format`.

```sh
base='https://script.google.com/macros/s/DEPLOYMENT_ID/exec'
curl -fsSL "$base"
curl -fsSL -H 'Content-Type: application/json' \
  --data-binary '{"app_version":"2.6.0","counters":{"activity":{"active":1},"path":{"start":1}},"schema_version":2}' \
  "$base"
```

Google ContentService отдаёт ответ через одноразовый URL `script.googleusercontent.com`. Приложение читает его отдельным GET без тела. Код HTTP 200 сам по себе не подтверждает сохранение. [ContentService и перенаправления](https://developers.google.com/apps-script/guides/content#redirects).

## Что остаётся в таблице

- Вкладка на каждую неделю получения (`2026-W47`): колонки `week`, `app_version`, `metric`, `code`, `total`. Неделю ставит скрипт по своим часам. Каждое сообщение суммируется с текущими значениями этой недели. Вкладка рассчитана на 6000 строк; при её заполнении сообщения отклоняются с причиной `full`.
- Вкладка «Приём»: `week`, `outcome` (`accepted` или `refused`), `reason` (`schema_1`, `schema_2` или причина отказа: `format`, `too_large`, `content_type`, `busy`, `storage`, `full`), `total`. Отказы, случившиеся пока таблица была занята другим запросом, временно копятся в свойстве скрипта `PENDING_REFUSALS` и переносятся в «Приём» следующим запросом; при одновременных запросах их число может быть занижено.
- Прежняя вкладка «Счётчики» (схема 1, без недель) остаётся нетронутой.

Незнакомый код или группа не губят сообщение: они считаются строкой `_unknown`, сам текст кода не сохраняется. На неделю хранится не больше 12 разных версий (остальные — `other`) и ограниченное число кодов в группе (лишние — `_other`). На входе требуется компактный ASCII JSON с отсортированными ключами не больше 16384 байт. [Схема диагностики](../docs/TELEMETRY.md).

Скрипт не сохраняет тела запросов, IP, идентификаторы и время отправки. В манифесте отключено журналирование исключений проекта. Google как хостинг может обрабатывать сетевые и служебные сведения по своим правилам. [Настройка манифеста](https://developers.google.com/apps-script/manifest).

Приёмник открыт на запись без входа в аккаунт. Посторонний клиент может отправить допустимую сводку и повлиять на суммы. Отключить приём можно в **Развернуть → Управление развертываниями**.

Если вкладок недель стало слишком много, старые можно скопировать в архив и удалить вручную; скрипт сам ничего не удаляет.

## Встроенная схема

`WIRE_SCHEMA` в начале `Code.gs` генерируется из `patient_importer/telemetry_schema.py` командой `python packaging/wire_schema.py`. Тест `tests/test_apps_script.py` проверяет совпадение.

## Локальная проверка кода

```sh
python -m unittest discover -s tests -p test_apps_script.py -v
```

Тесты запускают настоящий `Code.gs` в Node.js с имитацией сервисов Google. Разрешения аккаунта, перенаправления и запись в настоящую таблицу проверяются после развёртывания.
