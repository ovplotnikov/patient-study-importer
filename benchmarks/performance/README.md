# Синтетический аудит производительности 2.4.0

Скрипты создают вымышленные документы во временных папках. Не передавайте им рабочую папку врача. Прототипы меняют функции только внутри измерительного процесса; код приложения и релиз не меняются. Диагностика пользователей не используется.

Workflow `performance-audit.yml` последовательно запускает измерения на Windows и сохраняет только агрегированные результаты. Он не выпускает программу. Зависимости и OCR-веса соответствуют версии 2.4.0. Для запуска из исходников задайте `PYTHONPATH` равным корню checkout; параметры каждого скрипта доступны через `--help`.

- `startup.py`: опубликованный EXE, время до скрытого Tk и выхода; сравнение дублирующихся DLL по SHA-256. Это не время до готовности рабочего экрана. Кеш ОС не очищается, первый запуск отмечен отдельно.
- `e2e.py`: реальный импорт небольших текстовых бланков, добавление одного документа, дубли и пустая очередь.
- `storage.py`: текущий код и локальные прототипы индекса, каталога оригиналов, повторного использования стилей. Проверяет совпадение XML книги, заметок, формул, пользовательских листов, дедупликацию и SQLite.
- `ui_reads.py`: чтение базы, вызываемое интерфейсом, без отрисовки Tk; до 5000 синтетических документов с OCR-свидетельствами.
- `tk_queue.py`: создание и повторное заполнение настоящего списка Tk до 1000 ожидающих файлов в скрытом окне. Видимая перерисовка экрана в замер не входит.
- `analysis.py`: кеш даты страницы и индексы поиска кандидатов пациента; проверяет полное равенство вложенных результатов.
- `diagnostics.py`: стоимость чтения согласия и записи только вымышленных технических счётчиков, без сети. Сравнение с уже поддерживаемым аргументом количества отделяет стоимость I/O от будущей реализации безопасного группового сохранения.
- `ocr.py`: те же два движка, настройки и изображения; последовательное и параллельное исполнение, PNG через stdin, кеш идентичных вложений в одном PDF. Сравнивает полный результат OCR, разбора и контроля качества. Совпадение на этих примерах не доказывает качество на всех реальных бланках.

Числа относятся к конкретному runner и набору. Память разных процессов или этапов нельзя складывать по значениям их отдельных максимумов. Перед внедрением нужны обычные регрессионные проверки и проверка готовой Windows-сборки.
