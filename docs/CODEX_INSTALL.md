# Установка и обновление через Codex

Инструкция агенту на компьютере пользователя. Официальный источник: **https://github.com/ovplotnikov/patient-study-importer**. Готовая программа предназначена для Windows 10/11 x64. На macOS/Linux не пытайтесь запускать EXE и не обещайте нативную поддержку.

При установке без клонирования прочитайте `AGENTS.md` и эту инструкцию явно. Файл AGENTS.md задаёт правила работы агента внутри проекта, но не ограничивает технически доступ к файлам. [Документация OpenAI](https://developers.openai.com/codex/guides/agents-md).

## Границы задачи

- Обычная установка не требует исходников, Python, Tesseract или прав администратора. Для просмотра XLSX нужна совместимая программа.
- Установка работает с файлами программы и метаданными выпуска. Содержимое исследований, таблиц и базы для неё не требуется. Анализ документов — отдельная задача по запросу пользователя.
- Не выполнять `--import-folder`, `--self-test` или `--ui-smoke-test` для проверки установки у врача: они создают данные, а GUI-тест может изменить настройки.
- Не отключать Defender/SmartScreen и не менять системную политику выполнения скриптов. Если запуск блокируется, сообщить препятствие без обхода защиты.
- Не останавливать приложение принудительно. Попросить пользователя закрыть его после завершения обработки и дождаться закрытия.

## 1. Найти установку

Проверьте ОС и архитектуру. Для новой установки используйте `%LOCALAPPDATA%\Programs\PatientStudyImporter`. Не размещайте программу внутри checkout или папки исследований.

Для обновления найдите существующий EXE по ярлыку или уточните его расположение. Не сканируйте рекурсивно папки с исследованиями. Если установок несколько, уточните, какой пользуются. Не создавайте вторую установку молча.

Если рядом со старым EXE есть папка **Данные**, сохраняйте прежнее расположение EXE: программа может выбирать её при запуске. Не переносите эту папку. Настройки находятся в `%APPDATA%\PatientStudyImporter\settings.json`; не перезаписывайте их и не публикуйте их содержимое. Для установки они не нужны.

Если есть `installation.json` в папке программы, прочитайте только его: это служебная версия без медицинских данных. Если записи нет, считайте установленную версию неизвестной; надпись «2.0» в старом интерфейсе не определяет точный выпуск.

## 2. Найти стабильный выпуск

Страница: https://github.com/ovplotnikov/patient-study-importer/releases/latest

Пример получения метаданных публичного выпуска в PowerShell:

```powershell
$release = Invoke-RestMethod -Uri 'https://api.github.com/repos/ovplotnikov/patient-study-importer/releases/latest' -Headers @{ 'User-Agent' = 'PatientStudyImporter-Setup' }
if ($release.draft -or $release.prerelease) { throw 'Нужен стабильный опубликованный выпуск' }
$release.tag_name
```

Пока репозиторий закрыт, используйте имеющуюся авторизацию GitHub пользователя (`gh release view` / `gh release download`). Ошибка 404 может означать отсутствие доступа. Не ищите обходные копии на посторонних сайтах и не запрашивайте токен в чате. После открытия авторизация для скачивания не нужна.

Прочитайте описание выпуска: ограничения совместимости важнее общего порядка ниже. Скачивайте только Assets **PatientStudyImporter-Windows.zip** и **PatientStudyImporter-Windows.sha256** выбранного стабильного выпуска. Не используйте `Source code`, prerelease и временные Actions artifacts. Оба вложения должны быть доступны и полностью загружены.

## 3. Скачать и проверить

Создайте уникальную временную папку вне папки исследований. Скачайте оба вложения по `browser_download_url` из метаданных выпуска. Для закрытого репозитория можно использовать:

```text
gh release download <тег> --repo ovplotnikov/patient-study-importer --pattern "PatientStudyImporter-Windows.*" --dir <временная-папка>
```

До распаковки проверьте SHA-256:

```powershell
# $downloadDir — созданная агентом временная папка с двумя вложениями.
$zipPath = Join-Path $downloadDir 'PatientStudyImporter-Windows.zip'
$sumPath = Join-Path $downloadDir 'PatientStudyImporter-Windows.sha256'
$sum = (Get-Content -LiteralPath $sumPath -Raw).Trim()
if ($sum -notmatch '^([0-9a-fA-F]{64})\s+\*?PatientStudyImporter-Windows\.zip$') { throw 'Некорректный файл контрольной суммы' }
$expectedHash = $Matches[1]
if ((Get-FileHash -LiteralPath $zipPath -Algorithm SHA256).Hash -ne $expectedHash) { throw 'Контрольная сумма ZIP не совпадает. Установка остановлена' }
```

SHA-256 проверяет целостность скачивания, но не заменяет подпись издателя и доверие к аккаунту владельца. Проверьте список ZIP: в нём не должно быть абсолютных путей, `..`, ссылок за пределы каталога, папки «Данные», медицинских документов или баз. Распакуйте в новую временную подпапку, не поверх установленной программы. Ожидаются EXE, инструкция, лицензии и служебные сведения о сборке; в новых сборках также может быть `docs`.

В старых выпусках внутренний `SHA256.txt` имеет формат вывода PowerShell `Get-FileHash`. Основной обязательный контроль — внешний SHA-256 ZIP. Не считайте строку внутри `SHA256.txt` номером версии.

## 4. Установить или обновить

1. Дождитесь закрытия программы. Если EXE занят, остановите обновление и попросите закрыть приложение; не уничтожайте процесс.
2. Сохраните прежний EXE и известные служебные файлы программы в отдельной папке предыдущей версии. Не копируйте весь каталог рекурсивно: рядом могут быть исследования.
3. Скопируйте новый EXE во временное имя в целевой папке, сравните SHA-256 с распакованным EXE, затем замените `Исследования пациентов.exe`. Если замена не удалась, восстановите прежний EXE и сообщите об ошибке. Папку «Данные» и настройки не менять.
4. Обновите инструкцию, лицензии и документацию. Запишите `installation.json` с полями `repository`, `version` (тег), `archive_sha256`, `exe_sha256`, `installed_at`. Не включайте путь к данным, ФИО и медицинскую информацию.
5. Создайте или обновите ярлык **Исследования пациентов** на рабочем столе. Цель — этот EXE, рабочая папка — каталог программы. При обновлении сохраните корректный существующий ярлык.
6. Сообщите версию, путь программы, результат проверки хеша и путь прежнего EXE. Попросите пользователя открыть программу и проверить выбранную рабочую папку. Самостоятельно не запускайте импорт и не читайте содержимое окна с пациентами.

Если тег и SHA-256 установленного EXE совпадают с проверенным выпуском, повторная замена не нужна. Если тег совпал, но хеш другой, выясните причину или восстановите официальный EXE с сохранением предыдущего файла; не называйте такую установку проверенной.

Новая установка по умолчанию создаёт рабочую папку в `Documents\Исследования пациентов`, если не выбрана другая. Пользователь должен выбрать подходящее место. Если Documents синхронизируется с облаком, это влияет на хранение документов. Установка приложения не должна менять настройки облачной синхронизации.

## Восстановление и совместимость

При сбое замены до первого запуска верните прежний EXE. Откат EXE после работы новой версии не гарантирует совместимость изменённой базы: прочитайте примечания к выпускам. Не восстанавливайте базу и не удаляйте новые исследования автоматически.

Перед выпуском с изменением формата данных должны быть описаны резервное копирование и миграция. Если таких сведений нет, не угадывайте совместимость. Резервные копии внутри рабочей папки не заменяют отдельную копию, сделанную пользователем перед миграцией.

Итог пользователю: установленная версия, ссылка на выпуск, совпадение SHA-256, путь программы и ярлыка, путь предыдущего EXE. Отдельно подтвердите, что рабочие данные при установке не изменялись, если это действительно так. Начиная с 2.1.0, программа сама проверяет обновления при запуске и предлагает установку с согласия пользователя. Codex нужен для первой установки, перехода с 2.0.0 или помощи при проблемах. Установщик приложения заменяет только EXE и запись версии; файлы документации рядом с ним могут относиться к прежнему выпуску — актуальная инструкция всегда в репозитории.
