# Добровольная диагностика

Документы обрабатываются локально. Диагностика помогает увидеть, на каких этапах чаще возникают проблемы и какие причины сверки стоит разобрать в первую очередь. Для этого она отправляет только версии, фиксированные технические коды и сводные счётчики. Диагностика не собирает персональные данные пользователей или пациентов.

## Как включить или выключить

В сборке с настроенным сервисом приложение один раз предлагает выбор. Сбор начинается после явного согласия. Если закрыть предложение, диагностика останется выключенной. Решение сохраняется на компьютере и учитывается после обновления. Через **Помощь → Диагностика…** можно посмотреть состав данных и изменить выбор.

Отключение прекращает сбор и очищает очередь без ожидания ответа сервера. Запрос, отправка которого уже началась, может завершиться. Уже переданное сообщение отозвать через программу нельзя.

В сборке без адреса сервиса приложение не предлагает включить диагностику и ничего не отправляет в этот сервис. Обычная обработка работает без интернета. Проверка обновлений через GitHub остаётся отдельной функцией.

## Что входит в сообщение

Передаются версия формата сообщения, версия приложения и целые числа по заранее заданным кодам. Один файл может иметь несколько разных причин сверки. Повтор одной причины в нескольких строках этого файла не увеличивает счётчик этой причины.

| Группа | Что считается | Коды |
| --- | --- | --- |
| `formats` | Начатые попытки импорта по формату | `pdf`, `docx`, `txt`, `image`, `other` |
| `outcomes` | Итог попытки | `saved`, `duplicate`, `identity_review`, `quality_review`, `error`, `skipped` |
| `review_reasons` | Причины направления на сверку | Фиксированные коды, например `unknown_type`, `missing_date`, `OCR_DISAGREEMENT` |
| `review_outcomes` | Действия при сверке и повторной обработке | `confirmed`, `confirmed_incomplete`, `reprocessed`, `excluded`, `deferred` |
| `edit_categories` | Категории ручных изменений | `identity`, `study_type`, `study_date`, `result`, `unit`, `reference`, `observation`, `conclusion`, `other` |
| `failure_stages` | Этап или причина сбоя | `intake`, `extraction`, `analysis`, `storage`, `export`, `export_locked`, `archive`, `review` |

Полный список кодов `review_reasons`.

- Пациент и версия разбора — `missing_identity`, `ambiguous_identity`, `identity_from_ocr`, `legacy_parser`.
- Вид, дата и строки — `type_mismatch`, `conflicting_type`, `unknown_type`, `conflicting_date`, `missing_date`, `lab_no_results`, `missing_narrative_result`, `ambiguous_value`, `missing_result`, `missing_unit`, `unknown_unit`, `unmapped_columns`, `page_without_patient`, `unparsed_row`.
- OCR — `ocr_value`, `ocr_text`, `OCR_USED`, `OCR_DISAGREEMENT`, `OCR_ENGINE_UNAVAILABLE`, `OCR_LOW_CONFIDENCE`, `OCR_EMPTY`, `OCR_FAILED`.
- Чтение документа — `extraction_issue`, `PDF_TEXT_UNREADABLE`, `PDF_PAGE_EMPTY`, `EMBEDDED_IMAGE_UNREADABLE`, `EMBEDDED_IMAGE_UNSUPPORTED`, `SIGNATURE_IMAGE`, `DOCX_COMPLEX_CONTENT`, `DOCX_EXTRA_TEXT`.

В диагностике нет ФИО, контактов, значений и текстов из исследований, имён файлов и путей, дат отдельных действий, фотографий, журналов, сообщений исключений, идентификаторов пациента, документа, установки, устройства или пользователя.

Вымышленный пример сообщения, где из десяти попыток шесть потребовали сверки и четыре завершились без замечаний.

```json
{
  "schema_version": 1,
  "app_version": "2.4.0",
  "counters": {
    "formats": {"pdf": 10},
    "outcomes": {"quality_review": 6, "saved": 4},
    "review_reasons": {"unknown_type": 2}
  }
}
```

## Когда и куда отправляется

Выбор и неотправленные счётчики хранятся в настройках Windows, в файле `%APPDATA%\PatientStudyImporter\diagnostics\diagnostics.json`. Для интервала отправки там же хранится время последней попытки соединения. В сообщение оно не входит.

Программа пытается отправить сводку в фоне по HTTPS на настроенный адрес, когда накопилось не менее 10 попыток импорта, и делает это не чаще раза в сутки. Верхняя граница одного счётчика — 100 000. Сетевой сбой не мешает обработке документов.

При смене версии программы прежняя очередь сбрасывается, а выбор сохраняется. При смене адреса или условий сбора диагностика выключается. Включить её снова можно в настройках.

Приёмник принимает сообщения до 8192 байт и проверяет формат, допустимые коды, версию приложения и порог в 10 попыток. В хранилище остаются только суммы по версии, группе и коду. Отдельные импорты и входящие сообщения не сохраняются.

Сводка помогает выбрать проблемы для изучения. Она не измеряет точность OCR. Публичный адрес принимает допустимые по формату счётчики от любого клиента. Такие значения можно подделать. Из-за сетевого сбоя сводка может не дойти или поступить повторно.

## Варианты приёмника

- На отдельном сервере приёмник слушает `/v1/counters` и хранит суммы в SQLite. Он не сохраняет IP-адреса и не создаёт журналы запросов. Прокси и хостинг настраиваются отдельно.
- В Google Apps Script приёмник принимает POST на базовый адрес развёртывания с окончанием `/exec` и складывает счётчики в закрытой таблице Google Sheets, созданной владельцем. GET по тому же адресу проверяет доступность. Через этот адрес прочитать таблицу нельзя. Скрипт запрашивает разрешение `drive.file` на файлы, созданные или явно открытые через него, и использует только собственную служебную таблицу. Приложение получает только HTTPS-адрес приёмника, без ключей OAuth и разрешений на Диск. [Настройка приёмника](../google_apps_script/README.md), [модель доступа веб-приложений Google](https://developers.google.com/apps-script/guides/web#permissions).

Для Apps Script программа получает подтверждение отдельным GET по одноразовому адресу `script.googleusercontent.com`, без повторной отправки счётчиков. Доступность зависит от [квот Apps Script](https://developers.google.com/apps-script/guides/services/quotas). [Как Google возвращает ответ](https://developers.google.com/apps-script/guides/content#redirects).

Код Apps Script не записывает запросы в журналы. В манифесте отключено журналирование необработанных исключений. Google как оператор платформы может обрабатывать сетевые метаданные, включая IP-адрес, и вести служебные журналы. Эти записи находятся вне таблицы и не контролируются приложением. [Настройки манифеста](https://developers.google.com/apps-script/manifest#fields), [механизмы журналирования Google](https://developers.google.com/apps-script/guides/logging).

Начиная с версии 2.4.0 в конфигурации указан проверенный HTTPS-адрес развёртывания Google Apps Script. Приёмник поддерживает версии 2.4.0, 2.4.1 и 2.5.0. Сбор на каждом компьютере начинается после явного согласия. [Проверка развёртывания на вымышленных данных](TELEMETRY_VERIFICATION.md).

Согласие на диагностику касается только счётчиков. Материалы для поддержки бланков пользователь готовит и отправляет отдельно. [Правила обращения с данными](PRIVACY.md).
