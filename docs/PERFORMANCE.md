# Производительность и проверка изменений

Оптимизации сохраняют два независимых OCR-движка, проверки качества, ручную сверку, правила сопоставления пациентов, историю изменений и резервное копирование. Формат данных остаётся `registry-v2`.

## Что ускорено

- **Диагностика:** счётчики импорта объединяются в памяти и записываются одной атомарной операцией для каждого периода согласия. Отключение диагностики отменяет ещё не записанные счётчики; повторное включение не восстанавливает их. При аварийном завершении может потеряться незаписанная техническая статистика, но клинические данные сохраняются прежним способом.
- **Excel:** каталог сохранённых оригиналов читается один раз за экспорт; одинаковые стили ячеек используются повторно. Полный экспорт, резервные копии, формулы, заметки и пользовательские листы сохраняются.
- **SQLite и разбор:** индекс ускоряет поиск поступлений документа; сводка не загружает тяжёлые OCR-поля без необходимости; статусы читаются группой. Дата страницы разбирается один раз, кандидаты пациентов ищутся через индексы с прежним порядком результатов.
- **Интерфейс:** длинные списки показываются по 25 файлов; неизменившиеся строки не создаются заново при возврате в окно. Сохранение ручных решений выполняется в фоне. Общая блокировка исключает одновременные изменения рабочей папки, а закрытие программы ждёт завершения записи.
- **Предпросмотр:** окно сверки результатов хранит не более двух растровых страниц, суммарно до 8 млн пикселей. Выбор строки меняет рамку выделения без нового рендера. Многостраничный TIFF читается по выбранным кадрам. Вызовы PDFium сериализованы общим замком.
- **OCR:** Tesseract и PaddleOCR могут читать одну страницу одновременно. Размеры, модели, проверки и повторные проходы прежние. Дополнительная RGB-копия ограничена 18 млн пикселей (около 54 МБ); более крупные изображения оба движка читают последовательно в исходном разрешении. Внутри одного PDF успешное распознавание одинакового встроенного изображения используется повторно: максимум 16 записей с оценочным бюджетом 8 МиБ. Между файлами этот кэш не сохраняется.
- **EXE:** лишние корневые копии DLL Tesseract удаляются только при совпадении контрольных сумм и отсутствии зависимости других компонентов. Комплект DLL рядом с Tesseract сохраняется. Состав и хеши проверяются после сборки и записываются в `build-info.json`.

## Воспроизводимые измерения

Windows CI для PR и ручного запуска сравнивает рабочие пути текущего кода с исходниками опубликованной версии 2.4.0 (`f17e5f4`). Старый EXE загружается с проверкой SHA-256. Исходники запускаются в отдельных процессах с одинаковыми зависимостями и весами OCR. Оптимизации не подменяются тестовыми реализациями.

Только созданные с нуля вымышленные данные. Отчёты содержат длительности, размеры, счётчики и хеши результатов. Диагностический тест не отправляет запросы в сервис.

| Скрипт в `packaging/` | Сценарий и проверка |
| --- | --- |
| `compare_app_performance.py` | Дополнение базы из 100/1000 документов, точный и содержательный дубли; совпадение содержимого XLSX, заметки, формулы, дополнительного листа; целостность SQLite. Разбор страниц и сопоставление пациентов. |
| `compare_registry_performance.py` | Сводка большого синтетического реестра и статусы 500 документов; совпадение результатов. |
| `compare_diagnostics_performance.py` | 100/1000 попыток; совпадение отчётов, число записей состояния и сбросов на диск. |
| `compare_ui_performance.py` | Возврат фокуса при 10/100/1000 файлах; число виджетов и доступность всех файлов через страницы. |
| `compare_ocr_performance.py` | Чистый, повёрнутый, мелкий и перекошенный текст, скан PDF и повторённое изображение; полное совпадение текста, координат, уверенности движков, разбора и замечаний. |
| `compare_frozen_performance.py` | Первый запуск и три повтора штатного `--update-probe`, размеры EXE и распакованных ресурсов. |

Обычно выполняются три повторных измерения; отчёт содержит исходные замеры и медианы. JSON-файлы доступны в артефакте CI `performance-results`. Порог скорости не блокирует PR: нагрузка общего runner меняется. Несовпадение результатов или нарушение целостности блокирует проверку.

Сравнение XLSX исключает весь `docProps/core.xml`, содержащий изменяемые метаданные. Проверка запуска EXE измеряет импорт интерфейса и создание скрытого Tk, а не полную отрисовку рабочего окна. Память OCR на Windows относится к Python-процессу и не включает дочерний Tesseract. Первый запуск не означает сброшенные кэши Windows. Эти измерения не заменяют проверку на компьютерах пользователей и дополнительных формах.

Готовый EXE дополнительно проходит автономное OCR/PDF-тестирование, сценарии интерфейса, сохранение ручных решений и проверку обновлятора с сохранностью данных. Контракт диагностики и отсутствие посторонних полей проверяются отдельными тестами.
