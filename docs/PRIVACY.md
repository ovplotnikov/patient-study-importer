# Обращение с данными

## Работа программы

Программа не собирает для разработчика персональные данные пользователей или пациентов и не отправляет их ему. Документы и результаты хранятся в выбранной рабочей папке. Добровольная диагностика передаёт только техническую сводку без идентификаторов.

Документы читаются и распознаются локально, внешняя LLM/API для обработки не используется. В рабочей папке сохраняются исходные документы, распознанный текст, ФИО, даты рождения, результаты, база SQLite, Excel-таблица, журналы и резервные копии. Эти файлы содержат чувствительные сведения; их нельзя считать обезличенными.

Программа не шифрует базу и таблицу и не предоставляет разграничение доступа между сотрудниками. Доступ определяется настройками компьютера и места хранения. Самостоятельно выбранная облачная или сетевая папка может передавать данные за пределы компьютера. Это отдельное решение пользователя/организации.

## Проверка обновлений

С версии 2.1.0 при запуске выполняется запрос к публичному GitHub Releases. При согласии пользователя загружается выпуск и контрольная сумма. GitHub видит технические сведения о соединении, включая IP-адрес и версию программы в User-Agent. Содержимое исследований, базы, таблицы и путь рабочей папки в запросы не входят. Без интернета обработка документов доступна. [Политика конфиденциальности GitHub](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement).

## Добровольная диагностика

В сборке с настроенным сервисом можно согласиться на отправку сводных счётчиков обработки. Предложение показывается один раз. Выбор хранится на компьютере и сохраняется при обновлении. Через **Помощь → Диагностика…** можно посмотреть состав данных и изменить решение. Отключение останавливает сбор и очищает очередь без ожидания ответа сервера. Запрос, отправка которого уже началась, может завершиться. Проверка обновлений через GitHub работает отдельно.

В сводку входят версия программы, версия формата сообщения и счётчики по фиксированным техническим кодам. Например, программа считает, сколько раз встретила незнакомый вид бланка. В сводке нет персональных данных пациентов и пользователей, контактов, идентификаторов установки или устройства, содержимого документов, результатов, имён файлов, путей, изображений и журналов. Согласие на диагностику относится только к такой сводке.

При использовании Google Apps Script запросы обрабатывает Google, а итоговые суммы хранятся в закрытой таблице Google Sheets владельца сервиса. Публичный адрес предназначен для приёма счётчиков. Он не даёт доступа к таблице. Приложение не входит в аккаунт Google и не получает доступ к Диску. Приёмник сохраняет только суммы и не записывает запросы в журналы. Google может обрабатывать IP-адрес и другие служебные сведения о соединении и работе платформы. [Политика конфиденциальности Google](https://policies.google.com/privacy?hl=ru) · [Журналы Apps Script](https://developers.google.com/apps-script/guides/logging).

Без настроенного адреса сервиса приложение не предлагает диагностику, не собирает счётчики и не отправляет их. [Состав и условия отправки](TELEMETRY.md).

## Работа с Codex

Для установки и обновления достаточно файлов приложения и метаданных выпуска. Документы пациентов в репозитории отсутствуют, а локальная рабочая папка создаётся уже при использовании программы. Анализ её содержимого — отдельная задача, которую пользователь может явно поручить агенту. Правила в AGENTS.md описывают задачи агента, но не создают техническую изоляцию.

## Issues, PR и сообщения об ошибках

Допустимы версия программы, версия Windows, описание действий и воспроизведение на полностью вымышленных документах. Реальные ФИО, даты рождения, адреса, телефоны, номера карт/полисов, штрихкоды, подписи, заключения и связанные с ними результаты не должны попасть в публикацию. Имена файлов, пути, свойства документа, QR-коды и скриншоты тоже могут идентифицировать человека.

Не прикрепляйте `Данные`, `База`, `Резервные копии`, `Исследования.xlsx`, `last-error.txt` и исходные исследования. Не копируйте журнал целиком. Не загружайте ошибочный файл «сначала, чтобы разработчик удалил позже».

Для поддержки нового бланка подойдёт пустой шаблон без персональных сведений или пример, созданный с нуля. В примере можно использовать вымышленные ФИО **ТЕСТОВ ТЕСТ ТЕСТОВИЧ**, дату **01.01.2000** и вымышленные результаты. Скриншот делайте только с такого примера. Закрытие ФИО на готовом документе оставляет риск, что в нём сохранились другие идентификаторы, скрытый текст, история правок или метаданные.

Кнопка **Открыть письмо** открывает черновик на `info@inputlane.com` в вашей почтовой программе. В нём только готовый текст и версия программы. Вложения добавляете вы, а письмо уходит только после вашей команды отправки. При таком обращении поддержка получает адрес отправителя, письмо и добавленные вами вложения. Это отдельное действие пользователя вне диагностики.

## Если данные случайно попали в репозиторий

Не цитируйте их в новых сообщениях. Остановите дальнейшее распространение и сообщите владельцу только место утечки (ссылка/коммит/путь), не сами данные. Удаление из последнего коммита не удаляет историю Git; проверяются также теги, PR, артефакты, логи и выпуски. Для недоступных кэшей и удалённых объектов может потребоваться GitHub Support. Уже скачанные третьими лицами копии нельзя гарантированно отозвать.

Проверка перед открытием описывает технический охват и находки, а не является юридическим заключением или гарантией отсутствия любой возможности идентификации.
